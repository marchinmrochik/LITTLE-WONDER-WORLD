# Little Wonder design catalog

Local authoring and review tool for the existing Godot project. No accounts,
external requests, package installation, or hosting are needed.

## Start

From the repository root in PowerShell:

```powershell
.\tools\Run-DesignCatalog.ps1
```

Open http://127.0.0.1:8790. Keep the terminal running; Ctrl+C stops the server.
Use `-Port 8791` if the port is occupied. Requires Python 3.10+.
The existing local Godot installation is required for native previews.

## Review and change

1. Select a game/category or search by name, Ukrainian word, source path or ID.
2. Inspect the current illustration, audio, tracing path, source and usage.
3. Save a review status and note. These live in `design_catalog/reviews.json`.
4. For supported elements, prepare a replacement or edit tracing points/a shared
   UiKit color. This creates a draft; it does not change runtime files.
5. Compare the draft, explicitly apply it, then refresh Godot previews and open
   the affected game to check it. Restart an already running game after changes.
6. Use History to roll back a catalog change. A rollback refuses to overwrite
   files that have changed since that version was applied.

Illustration uploads require an author/source note, PNG or self-contained SVG,
and at most 16 MiB. Direct asset replacement keeps its original extension and
path, so every existing reference uses it. Procedural story replacements use
`assets/design/overrides/` and `data/game_content/design_visual_overrides.json`.
Tracing is edited separately in the game's original world coordinates.

## Coverage and limits

The current inventory contains 1,386 records, including 890 physical media
files (724 audio files), 46 procedural actors across four stories, 69 letter
and digit paths, content cards, 149 paints, shared colors, component source
entries and 15 game/world screen previews. Records can share one physical
asset; category counts are therefore not additive.

The catalog reads the actual project files. It does not maintain a duplicate
asset library. Native captures are generated by Godot: 178 images in the current
capture set. Press **Превью из Godot** after changing art or source. The first
run in a fresh checkout needs this action to populate native previews/palettes.

This is a first authoring foundation, not a general GDScript or animation editor:

- PNG/SVG artwork, tracing paths and shared UiKit colors have supported editors.
- Content/configuration and component source are inspectable; arbitrary code and
  game rules are not edited by the browser.
- Audio can be auditioned and reviewed. Speech replacement remains in the existing
  voice preparation/audit pipeline.
- Procedural actor previews cycle three genuine rendered states. Full interaction
  is checked with **Открыть ... в Godot** on isolated test saves.
- Replacing an actor with a bitmap preserves movement of the whole actor, existing
  hit targets and tracing. It does not create independently animated body parts.
- A source component without a dedicated sample is listed as source, not as an
  invented visual preview. Individual low-level drawing primitives are not assets.
- Images use contain fitting; artwork changes may require separate tracing/hit
  target work. Inspect the actual game before accepting a redesign.

## Files and safety

Drafts, native captures and byte-for-byte backups are under
`.local/design-catalog/` (Git-ignored). Keep that folder while a rollback may be
needed. Applied artwork/JSON/GDScript and review notes are normal project files.
The web tool itself is excluded from Android export.

The HTTP server binds only to loopback, validates Host/Origin and uses a random
per-process mutation token. Files are resolved against an inventory whitelist;
arbitrary filesystem browsing is unavailable. This is a single-user local tool;
do not expose it through a proxy or to the LAN. Source hashes reject stale drafts
and conflicting rollbacks. Backups protect normal apply/rollback operations;
this is not a replacement for Git or crash-safe multi-file database transactions.

## Verification

```powershell
python -m unittest discover -s tests -p test_design_catalog.py -v
node --check design_catalog/app.js
```

Mutation tests use a disposable fixture, never real game assets or child saves.
Native renderer: `tests/design_catalog_render.tscn`.
Isolated interactive preview: `tests/design_catalog_game_preview.tscn` (request
configuration is generated by the server).
